# ENM Rust construction measurement — 2026-10-10

Raw samples: [rust_enm_2026_10_10.json](rust_enm_2026_10_10.json).

Linux x86_64, Python 3.14.7, NumPy 2.4.6 / MKL 2025.3, Rust 1.98.1.
MKL, OpenMP, Numba and the serial Rust kernel each use one thread.
The selected source revision is `082b3f0ea518a63924ccb731b5259ba195b2c501`;
the private native binary is `cbae1e539c37f7ac131bde319a4fad2b6aaab53b7f5bfdb589ea83521481ff11`.
All 108 processes complete with matrix parity/symmetry and finite/residual checks.

Each first-use value is the median of three fresh-interpreter samples; each warm
value is the median of three per-process warm medians (three calls per process).
Times below cover **construction**, in milliseconds. They exclude interpreter/
scientific imports, contact preparation, backend import, validation reference and
diagonalization. First Numba construction includes JIT. Rust includes buffer
validation, snapshots, allocation and arithmetic. These synthetic geometric
graphs vary node count and cutoff; they are not a protein throughput claim.

These are absolute process RSS high-water marks, including suite imports, contacts,
engine loading/JIT and construction. They are not kernel-only allocation counts.
The output alone is 17.0 MiB. Rust avoids the dense NumPy construction intermediates;
the difference from Numba also includes JIT/compiler loading and cannot be assigned
entirely to numerical matrix storage. Allocator/host variation remains possible.

## Decision and practical limit

Warm ANM Rust construction is about 25–29 times faster than the current NumPy
construction at 497 nodes, but is about 11–26% slower than warmed serial Numba.
Its first kernel use is about 160–175 times faster than Numba including JIT;
engine-import and application initialization costs remain separate. GNM NumPy
is already competitive and beats this prototype in several construction cases.
A blanket claim that Rust is faster than NumPy/Numba is unsupported.

The unchanged NumPy eigensolver takes median 0.73–0.80 seconds at 497 ANM nodes
across these samples. Construction speedups therefore do not become 25–29 times
faster spectral queries. This tool executes eigh after parity; summing these
separate phases does not establish public-model end-to-end or first-query latency.
Saved/cached model queries do not reconstruct matrices at all.

The evidence supports a targeted ahead-of-time ANM route and removal of first-use
JIT costs, with measured memory benefits. Production selection still needs public
model calibration/trajectory/error/thread contracts and native installed delivery.
A serial Rust eigensolver was not tested; faer and sparse methods remain separate
decisions. Keep NumPy GNM as a valid candidate rather than forcing every operation
through the same implementation.

The development native gate passes 13 Python tests without skips plus 3 Rust
unit tests; NumPy matrix properties and full model regression are separate guards.
The requested-file adapter is subsequently hardened to require native loading,
including rejection of a Python substitute; kernel bytes used here do not change.

No native distribution/admission is inferred. See [the active proposal](../pending_proposals/rust_enm_kernels.md)
and [build/tool contracts](../../devtools/rust_enm/README.md).
